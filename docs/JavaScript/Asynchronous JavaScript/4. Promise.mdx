# Promise

在 ES6（ECMAScript 2015）中，Promise 正式成為 JavaScript 中的一部份標準，而那次的標準化，為開發者提供了統一的處理非同步的 API，解決了早期處理非同步碎片化的問題，大大提高了程式碼的可讀性、可移植性和可擴充性。

## Promise 的概念

以生活化例子來說的話，`Promise` 語法用起來會像是「你請 xxx 幫你做 ooo 事」，並在告知完後繼續做你自己的事情，不會在原地等待 ooo 的結果，並且你已經「事先規劃好」如果 ooo 事情往 A 方向發展，就做往 A 方向發展要做的事；如果 ooo 事情往 B 方向發展，就做往 B 方向發展要做的事。

- 想像你是一個開國中補習班的老闆，你打算擴大你的事業版圖，於是告知助理：「**幫我調查某國中附近的補習班數量**」，接著你就去做你自己的事了，並且你早已「事先規劃好」，會根據之後助理回報的結果，決定事情發展的方向，如果該國中附近補習班數量低於 3，你就會去開補習班；相反的如果數量高於 3，你會將這些學區加入觀察名單。

- 想像你是一個前端工程師，你正在開發一個查詢某圖書館藏書的功能，當使用者輸入書名按下查詢後，你的程式碼會做這件事:「根據使用者輸入的書名，**你請瀏覽器幫你從伺服器上取得書籍的資料**」，並且在搜尋的過程當中，使用者仍然可以上下滾動網頁，瀏覽其他資訊，並且你已經事先規劃好，如果書籍搜尋成功，就跳轉到顯示書籍相關資料的頁面；如果搜尋不到該書籍，就顯示查無此書的畫面。

使用 Promise 語法，最終會導向兩種結果：成功（Resolve）或失敗（Reject）。

`Promise` 內提供了這兩種函式`Resolve()`、`Reject()` 給開發人員，設計成功後要走什麼流程或做什麼事、失敗後要走什麼流程或做什麼事。

在程式中，你可以使用 `Promise` 的機制來處理非同步的操作，使用 `Promise` 的語法將整個非同步操作包起來，並根據操作完成後的結果走**成功**或**失敗**的流程。

## Promise 的基本語法

### Promise 的宣告

建立 Promise 最基本的方法，是使用 Promise 建構函式。

使用 Promise 建構函式時，一定要傳入一個 function 作為參數，其中傳入的 function 是有名稱的，叫做「**Executor function**」。

而 Executor function 需要再接收兩個參數：`resolve()` & `reject()`這兩個 function。

當非同步操作結束後，可以使用 `resolve()` 和 `reject()` 來決定要走成功的流程還是失敗的流程。<br />
若結果成功則將成功的結果丟進 `resolve()`，並透過 `.then()` 做成功要做的事；<br />
相反地，若結果失敗，則可將失敗的訊息丟進 `reject()`，並透過 `.catch()` 做失敗後要做的事。

e.g.

```javascript
// 先設計好一個 Executor function
const ExecutorFunction = (resolve, reject) => {
  /* 
    ...
    ...
    正在進行非同步操作....
    ...
    ...
  */

  if (非同步操作成功) {
    resolve("操作成功"); // 非同步操成功，呼叫 resolve function
  } else {
    reject("操作失敗"); // 非同步操失敗，呼叫 reject function
  }
};

// 記住，使用 Promise 建構函式時，一定要傳入一個 function 當做參數
const promise = new Promise(ExecutorFunction)
  .then(response => {
    // 成功後要做的事
    console.log(response);
  })
  .catch(error => {
    // 失敗後要做的事
    console.log(error);
  });
```

### Promise 的狀態

Promise 有三種狀態：

1. **Pending（進行中）**：Promise 剛被建立，並且尚未執行 Executor function。
2. **Fulfilled（已完成）**：Promise 已經執行 Executor function 中的 Resolve function。
3. **Rejected（已拒絕）**：Promise 已經執行 Executor function 中的 Reject function。

當 Promise 的狀態從 Pending 轉變為 Fulfilled 或 Rejected 時，Promise 的狀態就**不可再變更**。
