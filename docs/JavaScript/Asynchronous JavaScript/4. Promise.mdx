# Promise

在 ES6（ECMAScript 2015）中，Promise 正式成為 JavaScript 的一部份標準，而那次的標準化，為開發者提供了一致的處理非同步的方式，解決了早期處理非同步不一致的問題，大大提高了程式碼的可讀性和可擴充性。

## Promise 的概念

在講 Promise 的語法之前，我們先用生活化的例子來建立基本的概念。

`Promise` 語法用起來會像是「你請 xxx 幫你做 ooo 事」，並在通知後繼續做你自己的事情，你可以到處亂晃不用在原地等待 ooo 的結果，並且對於 ooo 的結果早已「事先規劃好」，如果 ooo 的結果為 A，就往 A 方向發展；如果 ooo 的結果為 B，就往 B 方向發展。

例：

- 想像你是一個網頁工程師，你正在開發一個查詢圖書館藏書的功能，當使用者輸入書名按下查詢後，你的程式會根據使用者輸入的書名查詢對應的書籍（也就是你請瀏覽器幫你對 Server 發出查詢書籍的訊號），而且在搜尋的過程中，使用者仍然可以到處亂晃（例如上下滾動網頁，瀏覽其他資訊），並且你早已「事先規劃好」，如果書籍搜尋成功就跳轉到「顯示書籍細節的頁面」；如果搜尋不到該書籍就「顯示查無此書的畫面」。

找到書籍 => 代表搜尋成功 => 顯示書籍細節頁面<br />
找不到書籍 => 代表搜尋失敗 =>　顯示查無此書的畫面。

從這個例子中你會發現結果有兩種：**成功或失敗**。（什麼結果是成功，什麼結果是失敗，可以由你自己決定）

我們透過使用 `Promise` 語法將『非同步操作包起來』，並根據結果走**成功**或**失敗**的流程。

## Promise 的宣告

建立一個 Promise 最簡單的方法是使用 `Promise 的建構函式`。

如下例：

使用 Promise 建構函式時，一定要傳入一個 function 作為參數，參數是有名稱的，叫做「**Executor function**」。

你可以在 Executor function 內設計任何非同步操作，例如：發送網路請求、讀取檔案、等待計時器等。<br />

Executor function 需要再接收兩個參數：`resolve()` & `reject()`。這兩個參數都是 function，分別用來決定非同步操作後的結果是成功還是失敗。若結果成功則執行 `resolve()`、若結果失敗則執行 `reject()`，如下例：

```javascript
// 設計一個 Executor function，並傳入兩個參數
const ExecutorFunction = (resolve, reject) => {
  /* 
    進行非同步操作 ...
  */
  if (非同步操作成功) {
    resolve("操作成功"); // 非同步操成功，呼叫 resolve function（ resolve function 接受任何參數 ）
  } else {
    reject("操作失敗"); // 非同步操失敗，呼叫 reject function（ reject function 接受任何參數 ）
  }
};

// 由 Promise 語法將非同步操作包起來
const example = new Promise(ExecutorFunction);
```

當非同步操作完成後，可以自行設計什麼結果是成功、什麼結果是失敗，再觸發要走成功的流程還是失敗的流程，如下例：

使用 `resolve()` 代表非同步操作成功、使用 `reject()` 代表非同步操作失敗。若結果成功，則將成功的資料丟進 `resolve()`，並透過 `.then()` 做成功要做的事；相反地，若結果失敗，則可將失敗的錯誤資訊丟進 `reject()`，並透過 `.catch()` 做失敗後要做的事。

```javascript
const ExecutorFunction = (resolve, reject) => {
  /* 
    進行非同步操作 ...
  */

  if (非同步操作成功) {
    resolve("操作成功"); // 非同步操成功，呼叫 resolve function
  } else {
    reject("操作失敗"); // 非同步操失敗，呼叫 reject function
  }
};

// 記住，使用 Promise 建構函式時，一定要傳入一個 function 當做參數
const promise = new Promise(ExecutorFunction)
  .then(response => {
    /*
      做結果是成功後要做的事
    */
    console.log(response); // 印出 "操作成功"
  })
  .catch(error => {
    /*
       做結果是失敗後要做的事
    */
    console.log(error); // 印出 "操作失敗"
  });
```

## Promise 的狀態

Promise 有三種狀態：`Pending`、`Fulfilled` 和 `Rejected`。

1. **Pending（進行中）**：表示 `Promise` 剛被建立，尚未執行 `Resolve` function 或 `Reject` function。
2. **Fulfilled（已完成）**：`Promise` 已執行完 `Resolve` function。
3. **Rejected（已拒絕）**：`Promise` 已執行完 `Reject` function。

當 Promise 的狀態從 Pending 轉變為 Fulfilled 或 Rejected 時，Promise 的狀態就**不可再變更**！<br />
這意味著一旦 Promise 被解決（Fulfilled）或拒絕（Rejected），它就不會再變回 Pending 狀態。

這是 Promise 重要的特性，確保 Promise 的狀態是不可變的，避免在程式中出現不一致的狀態，也使得 Promise 的使用更加簡單和可靠，因為你不需要擔心 Promise 的狀態會在其他地方被意外地改變，使得 Promise 的行為更加可預測，並且能夠更好地處理非同步操作的結果。

## Promise 的其他應用

### Promise.all()

Promise.all() 是 JavaScript 中的內建靜態方法，可以直接使用不需要先實例化。

Promise.all() 接受一個「可迭代」的物件（通常是一個陣列，陣列內含多個 Promise），當所有的 Promise 都成功時，Promise.all() 會 return 一個新的 Promise，這個新 Promise 的狀態取決於所有輸入 Promise 的結果，如果有任何一個 Promise 的狀態是 Rejected，則立刻 return 第一個被拒絕的錯誤；若都成功則狀態是 Fulfilled。這意味著 Promise.all() 會等待所有的 Promise 都完成才會進行後續的操作。

這就像你同時派多個人去完成不同任務，只有當所有人都成功完成時，整體才算完成；但只要有一個人失敗，整個計畫就立刻中止。

#### 基本語法

```javascript
const results = Promise.all(iterable);
```

- iterable：表示一個可迭代的物件 (通常是一個陣列)，陣列元素通常是 Promise，但也可以不是 Promise（JS 會自動轉為已解決的 Promise）。
- Promise.all() 會回傳一個 Promise，其狀態如下：
  - **成功（fulfilled）**：當所有 Promise 都成功時，回傳的 Promise 狀態才會成功，且回傳的值是一個陣列，按輸入順序包含每個 Promise 的成功值。
  - **失敗（rejected）**：只要有一個 Promise 失敗，回傳的 Promise 會立即失敗，並傳遞第一個失敗的錯誤原因（後續的 Promise 結果會被忽略）。
- 所有的 Promise 會並行執行，而不是一個接一個，這是 Promise.all() 的核心優勢。

#### 簡單範例

```javascript
const promise1 = Promise.resolve(3); // Promise.resolve 是一個靜態方法，會回傳一個已解決的 Promise
const promise2 = new Promise(resolve => setTimeout(resolve, 3000, "foo")); // 3 秒後回傳 "foo"
const promise3 = 42; // 非 Promise 值會被轉為 Promise.resolve(42)

Promise.all([promise1, promise2, promise3])
  .then(results => {
    console.log(results); // [3, 'foo', 42]
  })
  .catch(error => {
    console.error(error);
  });
```
