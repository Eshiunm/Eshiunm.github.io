# Promise

在 ES6（ECMAScript 2015）中，Promise 正式成為 JavaScript 中的一部份標準，而那次的標準化，為開發者提供了統一的處理非同步的 API，解決了早期處理非同步碎片化的問題，大大提高了程式碼的可讀性、可移植性和可擴充性。

## Promise 的概念

以生活化的例子來說的話，`Promise` 語法用起來會像是「請某人幫你做某事」，對方答應了，並且「承諾」未來會給你一個結果，不論結果是成功或失敗。

想像你正在逛網拍，看到一個你很喜歡的商品，於是你手刀下訂單「**請商家出貨**」，接著收到 e-mail，信件內容提到「**商品會在三個工作天內出貨**」。

「請商家出貨」就是**請某人幫你做某事**；「商品會在三個工作天內出貨」就是對方給你的**承諾**。

而承諾這件事，最終會導向兩個結果：成功（Resolve）或失敗（Reject）。<br />
`Promise` 內提供了這兩種函式`Resolve()`、`Reject()` 給開發人員，設計成功後要走什麼流程、失敗後要走什麼流程。

以這個例子來說，如果商家在三天內出貨，那就是 Resolve，走買家拿到貨的流程；如果商家沒有在三天內出貨，那就是 Reject，走買家退款的流程。

在程式中，你可以使用 `Promise` 的機制來處理非同步的操作，讓 `Promise` 的語法結構將整個非同步操作包起來，並根據操作完成後的結果走**成功**或**失敗**的流程。

## Promise 使用時機

在以下情境使用 Promise 特別合適：

1. 處理非同步操作：如 AJAX 請求、檔案操作、定時器等
2. 需要照順序地執行多個非同步任務
3. 需要並行地執行多個非同步任務並等待全部完成
4. 需要競爭執行多個非同步任務並取得最快完成的結果
5. 需要更優雅的錯誤處理機制

## Promise 的基本用法

### Promise 的宣告

建立 Promise 最基本的方法，是使用 Promise 建構函式，使用 Promise 建構函式時，一定要傳入一個 function 作為參數，其中傳入的 function 是有名稱的，叫做「**Executor function**」。

而 Executor function 需要再接收兩個參數，個別是 `resolve()` 和 `reject()`這兩個 function。當非同步的操作結束時，可以透過 `resolve()` 和 `reject()` 來處理操作後的結果，若結果成功則使用 `resolve()` 做成功後要做的事；相反地，若結果是失敗的則使用 `reject()` 做失敗後要做的事。

e.g.

```javascript
const ExecutorFunction = (resolve, reject) => {
  // 非同步操作
  // 非同步操成功，呼叫 resolve function
  // 非同步操失敗，呼叫 reject function
};

// 記住，使用 Promise 建構函式時，一定要傳入一個 function 當做參數
const promise = new Promise(ExecutorFunction);
```

### Promise 的狀態

Promise 有三種狀態：

1. **Pending（進行中）**：Promise 剛被建立，並且尚未執行 Executor function。
2. **Fulfilled（已完成）**：Promise 已經執行 Executor function，並且成功完成。
3. **Rejected（已拒絕）**：Promise 已經執行 Executor function，但是失敗。

當 Promise 的狀態從 Pending 轉變為 Fulfilled 或 Rejected 時，Promise 的狀態就**不可再變更**。
