Promise

在 ES6（ECMAScript 2015）中，Promise 正式成為 JavaScript 中的一部份標準，而那次的標準化，為開發者提供了統一的處理非同步的 API，解決了早期處理非同步碎片化的問題，大大提高了程式碼的可讀性、可移植性和可擴充性。

Promise 的概念​

以生活化例子來說的話，Promise 語法用起來會像是「你請 xxx 幫你做 ooo 事」，並在告知完後繼續做你自己的事情，不會在原地等待 ooo 的結果，並且你已經「事先規劃好」如果 ooo 事情往 A 方向發展，就做往 A 方向發展要做的事；如果 ooo 事情往 B 方向發展，就做往 B 方向發展要做的事。

例：

  • 想像你是一個開國中補習班的老闆，你打算擴大你的事業版圖，於是告知助理：「幫我調查某國中附近的補習班數量」，接著你就去做你自己的事了，並且你早已「事先規劃好」會根據助理調查的結果決定事情發展的方向，如果該國中附近補習班數量低於 3，你就會去開補習班；相反的如果數量高於 3，你會將這些學區加入觀察名單。

  • 想像你是一個前端工程師，你正在開發一個查詢某圖書館藏書的功能，當使用者輸入書名按下查詢後，你的程式會根據使用者輸入的書名「請瀏覽器幫你從伺服器上取得書籍的資料」，而且在搜尋的過程中，使用者仍然可以上下滾動網頁，瀏覽其他資訊，並且你已經「事先規劃好」，如果書籍搜尋成功就跳轉到顯示書籍細節的頁面；如果搜尋不到該書籍，就顯示查無此書的畫面。

從上面兩個例子中你可以發現最終都會導向兩種結果，成功或失敗。
補習班數量低於 3 或找到書籍 => 代表結果成功 => 開補習班或顯示書籍細節頁面
補習班數量高於 3、或找不到書籍 => 代表結果失敗 => 加入觀察名單或顯示查無此書的頁面。

在程式中，你可以使用 Promise 機制來處理非同步操作，透過使用 Promise 語法將整個非同步操作包起來，並根據操作完成後的結果走成功或失敗的流程。

Promise 的基本語法​

Promise 的宣告​

建立一個 Promise 最簡單的方法是使用 Promise 建構函式。

使用 Promise 建構函式時，一定要傳入一個 function 作為參數，其中傳入的 function 是有名稱的，叫做「Executor function」。

在 Executor function 中，你可以設計任何非同步操作，例如：發送網路請求、讀取檔案、等待計時器等。
而 Executor function 需要再接收兩個參數：resolve() & reject()。這兩個參數都是 function，分別用來處理非同步操作後的結果，若成功則呼叫 resolve()，若失敗則呼叫 reject()。

// 設計一個 Executor function，並傳入兩個參數
const ExecutorFunction = (resolve, reject) => {
  /* 
    進行非同步操作 ...
  */
  if (非同步操作成功) {
    resolve("操作成功"); // 非同步操成功，呼叫 resolve function
  } else {
    reject("操作失敗"); // 非同步操失敗，呼叫 reject function
  }
};

// 將 Executor function 丟進 Promise 建構函式
// 也就是由 Promise 語法將非同步操作包起來
const example = new Promise(ExecutorFunction);

當非同步操作完成後，你可以根據結果來決定要走成功的流程還是失敗的流程。
使用 resolve() 來代表非同步操作成功、使用 reject() 來代表非同步操作失敗。
若結果成功，則將成功的資料丟進 resolve()，並透過 .then() 做成功要做的事；
相反地，若結果失敗，則可將失敗的資料丟進 reject()，並透過 .catch() 做失敗後要做的事。

const ExecutorFunction = (resolve, reject) => {
  /* 
    進行非同步操作 ...
  */

  if (非同步操作成功) {
    resolve("操作成功"); // 非同步操成功，呼叫 resolve function
  } else {
    reject("操作失敗"); // 非同步操失敗，呼叫 reject function
  }
};

// 記住，使用 Promise 建構函式時，一定要傳入一個 function 當做參數
const promise = new Promise(ExecutorFunction)
  .then(response => {
    // 成功後要做的事
    console.log(response);
  })
  .catch(error => {
    // 失敗後要做的事
    console.log(error);
  });

宣告 Promise 的兩種方式：​

  • 1.立即執行的 Promise
  • 2.等待被呼叫的 Promise

以下宣告方式，會在 Promise 建立完成後立刻執行。

console.log("程式開始");
console.log("準備建立 Promise...");

// Promise 一建立好就會立即執行
const immediatePromise = new Promise((resolve, reject) => {
  console.log("Promise 建立好了。")
  console.log('立即執行 Promise！');

  // 做一些事情...
  console.log("執行非同步操作中...")
  setTimeout(() => {
    console.log("３秒後...");// or 非同步操作失敗！
    resolve('非同步操作成功！');　// or reject('失敗');
  }, 3000);

}).then(response => {
  console.log(response);
}).catch(error => {
  console.log(error) // 這個例子不會執行到這裡
});
console.log("程式繼續執行...");

程式繼續執行...

非同步操作成功！

不過什麼時候會需要用到立即執行 Promise 的情境呢？當這個 Promise 只需要執行一次時。
例如：當頁面載入時需要獲取的資料。

以下宣告方式，會在 Promise 被呼叫時才執行。

// 建立一個回傳 Promise 的函式
const delayedPromise = () => {
  return new Promise((resolve, reject) => {
    console.log('只有在函式被呼叫時才會執行 Promise');

    // 做一些事情...
    console.log("執行非同步操作中...")
    setTimeout(() => {
      console.log("３秒後，非同步操作成功！");// or 非同步操作失敗！
      resolve('完成');　// or reject('失敗');
    }, 3000);
  });
};

console.log("程式開始");
console.log("呼叫 Promise 函式");
delayedPromise();
console.log("程式繼續執行...");

執行結果：

程式開始
呼叫 Promise 函式
只有在函式被呼叫時才會執行 Promise
執行非同步操作中...
程式繼續執行...
３秒後，非同步操作成功！

使用情境：

  • 當你需要重複使用同一個 Promise 邏輯
  • 當你需要在特定條件下才執行 Promise
    • 例如：使用者點擊按鈕時才需要執行的操作

將上面提到的例子轉成 promise 呈現：

  • 開補習班的例子
  • 查詢圖書館藏書的例子
const ExecutorFunction = (resolve, reject) => {
  console.log("助理開始調查某國中學區附近的補習班數量");
  console.log("助理調查中...");

  setTimeout(() => {
    console.log("助理調查完成！");
    const numberOfTutoringClasses = 2; // 假設有 3 間補習班
    if (numberOfTutoringClasses < 3) {
      resolve("開設補習班");
    } else {
      reject("加入觀察名單");
    }
  }, 3000);
};

const promise = new Promise(ExecutorFunction);

執行結果:

助理開始調查某國中學區附近的補習班數量
助理調查中...
助理調查完成！
開設補習班

Promise 的狀態​

Promise 有三種狀態：

  1. Pending（進行中）：Promise 剛被建立，並且尚未執行 Executor function。
  2. Fulfilled（已完成）：Promise 已經執行 Executor function 中的 Resolve function。
  3. Rejected（已拒絕）：Promise 已經執行 Executor function 中的 Reject function。

當 Promise 的狀態從 Pending 轉變為 Fulfilled 或 Rejected 時，Promise 的狀態就不可再變更。
