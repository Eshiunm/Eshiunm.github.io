What is OOP？

Object-oriented programming（OOP，物件導向），是一種 以物件概念為基礎 的程式設計方法。

當我們說物件導向是一種「程式設計方法」時，代表程式設計有很多種方法，而物件導向是其中一種。

像建築師在規劃一棟建築物時，可以選擇不同的建築風格和設計原則，
程式設計也有諸多不同的方法可以選擇，物件導向就是其中一種非常重要且廣泛使用的方法。

「以物件概念為基礎」這部份特別重要。
因為它代表在物件導向程式設計中，我們把程式的元素都視為「物件」，並將這些物件看作是「現實世界中的實體」或「一種抽象功能」，其中物件擁有自己的特性（屬性）和行為（方法）。

這種設計方法，讓程式的結構更接近我們對現實世界的認知，使得程式更容易理解和維護，因此 OOP 除了是一種寫程式的方法，更是一種模擬真實世界和組織真實世界資訊的方法。

為什麼要模擬真實世界？​

因為我們需要透過程式處理現實世界的問題。

為了讓電腦能夠理解和處理現實世界的問題，我們需要找到一種方式，將現實世界的事物和概念，轉換成電腦可以理解的形式，而「物件」就是這樣的一個橋樑。

讓我們看看將兩種不同類型的資訊模擬成物件：

真實世界的模擬

如果我們要開發一個圖書館管理系統，在物件導向的思維下，我們可能會有以下物件：

  • 「書籍」物件：包含書名、作者、出版日期等特性。借出、歸還等行為
  • 「讀者」物件：包含姓名、會員編號等特性。借書、還書等行為
  • 「圖書館」物件：包含館藏數量、位置等特性。開館、閉館等行為
抽象功能的模擬

有些時候，我們需要處理的是看不見摸不著的概念。例如，一個銀行系統中的「帳戶」物件：

  • 抽象的特徵：帳戶餘額、帳戶狀態
  • 虛擬的行為：轉帳、存款、提款
  • 邏輯概念：交易限制、利率計算

這種模擬成物件的方式，優點在於：

  1. 直覺理解：當我們將程式元素設計成貼近現實或符合邏輯的物件時，其他程式設計師更容易理解這個系統在做什麼。
  2. 彈性處理：物件可以根據需求被調整和擴充。例如，我們可以輕易地在寵物物件中添加新的特徵（如晶片編號）或新的行為（如美容服務）。
  3. 結構清晰：通過物件的方式來組織程式，可以讓整個系統的結構更加清晰，就像是在建造一個模型，每個零件都有其特定的位置和功能。
  4. 重複使用：一旦我們設計好了一個物件模型，它就可以在不同的場景中被重複使用。例如，「帳戶」物件的設計可以用在銀行系統、電子錢包、或是遊戲幣系統中。

物件的組成來自於兩個部分：屬性 & 方法​

知道為什麼要將程式的資料模擬成真實世界後，我們來看看物件的組成。

物件的組成：

  • 屬性

    ：用來描述物件「有什麼」特徵。例如一個「手機」物件，屬性可能會包含這支手機的基本資訊：

    • 品牌名稱
    • 型號
    • 螢幕大小
    • ……

  • 方法 ：用來描述物件「能做什麼」行為、動作、功能。例如一個「手機」物件，方法可能會包含：

    • 撥打電話
    • 傳送訊息
    • 拍照
    • ……
